# طرح MVP و برنامه تحویل

این سند محدوده‌ی MVP، اسپرینت‌ها و خروجی‌های لازم برای تحویل نسخه‌ی اولیه‌ی سامانه را مشخص می‌کند.

## 1. اهداف MVP
پزشک بتواند:
- نوبت بگیرد (آنلاین و دستی)
- بیمار ثبت کند
- ویزیت ثبت کند
- نسخه چاپ کند
- پرداخت آنلاین انجام دهد

## 2. دامنه‌ی دقیق MVP (تحویل اول)
1. **Appointment Core**: تقویم روزانه/هفتگی، ایجاد نوبت دستی/آنلاین، لینک اختصاصی رزرو، OTP/Confirmation SMS، وضعیت‌ها (reserved, cancelled, attended, no_show).
2. **Mini EMR**: پروفایل بیمار، ثبت ویزیت ساده (diagnosis, recommendations, meds[])، چاپ نسخه PDF ساده.
3. **Payments & Finance**: پرداخت آنلاین هنگام رزرو، گزارش ساده روزانه/ماهانه، کیف پول ابتدایی + مانده.
4. **Settings**: اطلاعات مطب، ساعت کاری، قالب پیامک، قیمت ویزیت.
5. **Receptionist Panel (ساده)**: مشاهده نوبت‌های امروز، ثبت بیمار، ثبت پرداخت نقدی.
6. **Support پایه**: تیکت/یادداشت داخلی در سطح نوبت/بیمار.

## 3. اسپرینت پیشنهادی (مثال 3 اسپرینت، هر کدام 2 هفته)
- **اسپرینت 1**: هسته پلاگین، Module Registry، دیتابیس پایه، REST پایه، ایجاد نوبت آنلاین/دستی، SMS OTP، جلوگیری از double-booking.
- **اسپرینت 2**: Mini EMR، چاپ نسخه PDF، پرداخت آنلاین و webhook، گزارش مالی ساده، داشبورد منشی.
- **اسپرینت 3**: بهینه‌سازی UX mobile-first، تنظیمات ماژول‌ها، لاگ‌ها و گزارش اولیه، مستندات نصب و API (OpenAPI/Postman)، hardening امنیت.

## 4. Acceptance Criteria (MVP)
1. رزرو آنلاین بدون double-booking در تست کانکارنسی.
2. منشی می‌تواند نوبت دستی بسازد و وضعیت را تغییر دهد.
3. رزرو با OTP بدون ثبت‌نام کامل ممکن است.
4. پرداخت آنلاین در رزرو و پردازش webhook ثبت می‌شود.
5. پروفایل بیمار و ثبت ویزیت ساده + چاپ PDF نسخه فعال است.
6. لاگ خطا و گزارش ابتدایی در دسترس است.
7. مستندات نصب و API منتشر شده است.

## 5. Deliverables
- سورس کد پلاگین و ماژول‌ها (Git) + branchهای مشخص.
- مستندات نصب/راه‌اندازی و ERD.
- OpenAPI/Swagger یا Postman Collection.
- تست‌های Unit/Integration پایه + گزارش Load test رزرو.
- نسخه‌ی نصب‌شده‌ی staging با داده‌ی نمونه و دسترسی تست.

## 6. ریسک‌ها و کاهش ریسک
- **همزمانی رزرو**: قفل سطح رکورد یا صف رزرو + تست k6.
- **وابستگی به درگاه SMS/پرداخت**: Adapter + fallback و مانیتورینگ خطا.
- **عملکرد**: ایندکس مناسب + caching + سقف نرخ API.
- **امنیت**: Rate limit، Nonce/JWT، Prepared Statements، RBAC.

## 7. نقشه‌ی استقرار اولیه
- محیط Staging روی PHP 8.1+ و MySQL 8 (InnoDB)، Redis برای Object Cache/Queue.
- CI ساده: lint + PHPUnit + static analysis؛ CD برای deploy به staging.
- مانیتورینگ: لاگ ساختاریافته، alert برای خطای پرداخت/SMS، health-check endpoint.
