# سامانه مدیریت مطب/کلینیک مبتنی بر WordPress

این مخزن شامل طراحی معماری، ماژول‌ها و برنامه‌ی تحویل MVP یک سامانه مدیریت مطب/کلینیک است که به‌صورت پلاگین ماژولار وردپرس (به‌همراه سرویس‌های مکمل) قابل پیاده‌سازی است. تمرکز بر یکپارچگی، ماژولار بودن، امنیت، کارایی و mobile-first بودن است.

## محتوای اصلی
- [`docs/architecture.md`](docs/architecture.md): معماری کلان، ماژول‌ها، لایه‌بندی، دیتابیس و API.
- [`docs/mvp-plan.md`](docs/mvp-plan.md): محدوده و تحویل MVP، اسپرینت‌ها و معیارهای پذیرش.
- [`docs/plugin-design.md`](docs/plugin-design.md): ساختار پوشه‌ها، رجیستری ماژول، کانتینر سرویس، امنیت و الگوی تست.
- [`docs/api-design.md`](docs/api-design.md): قراردادهای REST برای MVP (رزرو، EMR، پرداخت، OTP و وبهوک‌ها).
- `plugin/clinic-manager/`: نمونه‌ی اولیه پلاگین ماژولار وردپرس شامل Module Registry، Service Container و ماژول‌های نوبت‌دهی، دایرکتوری پزشک/خدمات، EMR، مالی، تنظیمات، پیامک/اتوماسیون، رشد/مارکتینگ، پشتیبانی و API Gateway/Webhooks.
- داشبورد منشی/مدیریت در ادمین وردپرس برای مشاهده نوبت‌های پیش‌رو و تغییر سریع وضعیت‌ها.
- شورتکدهای ساده‌ی فرانت‌اند: `[ms_provider_directory]` برای نمایش کارت‌های پزشکان منتشرشده و `[ms_booking_form]` برای ثبت نوبت آنلاین (فورم ساده + call به REST).

## نکات کلیدی
- معماری یکپارچه اما ماژولار با **Module Registry** برای enable/disable بدون تخریب داده.
- استفاده از OOP و لایه‌های Presentation / Service / Repository با hooks & filters استاندارد WordPress.
- طراحی API-first و آماده‌ی اتصال اپلیکیشن‌های بیمار و پزشک.
- امنیت، مقیاس‌پذیری و تست‌پذیری در سطح هسته و ماژول‌ها.

### وضعیت فعلی و قابلیت استفاده
- کد پلاگین در مسیر `plugin/clinic-manager` یک نمونه‌ی اولیه‌ی MVP است و برای اجرا روی نصب تازه‌ی WordPress 6.4+ نیاز به **نصب دستی** دارد (کپی پوشه پلاگین، فعال‌سازی از ادمین و اجرای hookهای ایجاد جدول در اولین فعال‌سازی).
- همه ماژول‌های اصلی (نوبت‌دهی، EMR، مالی، پیامک/OTP، دایرکتوری، رشد، پشتیبانی، تنظیمات و درگاه وبهوک) ثبت شده‌اند، اما **UI فرانت‌اند بیمار/پزشک و قالب‌های نمایشی آماده نیست** و باید با shortcode/تم سفارشی یا توسعه‌ی فرانت جداگانه تکمیل شود.
- REST APIها، مدل داده و کنترل دسترسی‌ها (نقش‌های Clinic Manager/Provider/Receptionist و قابلیت‌های `ms_manage_*`) پیاده‌سازی شده‌اند و می‌توان برای تست با Postman یا کلاینت سفارشی استفاده کرد؛ با این حال برای محیط production نیاز به **سخت‌گیری بیشتر در امنیت، لاگینگ و مانیتورینگ** دارید.
- برای استفاده واقعی باید تنظیمات پایه (اطلاعات کلینیک، ساعت کاری، قالب پیامک، درگاه پرداخت) از طریق endpointهای تنظیمات یا داخل دیتابیس اعمال شود و اتصال واقعی SMS/پرداخت در adapterهای مربوطه پیاده‌سازی یا پیکربندی شود.
- داشبورد منشی در ادمین وردپرس تنها یک نمای لیست نوبت‌های پیش‌رو و تغییر وضعیت سریع است؛ برای تجربه کامل reception و بیمار، توسعه UI تکمیلی (React/Vue یا template سفارشی وردپرس) لازم است.

### نقش‌ها و دسترسی‌ها
- **Clinic Manager**: دسترسی کامل به همه‌ی ماژول‌ها و تنظیمات.
- **Clinic Provider**: مدیریت نوبت‌ها، EMR، دایرکتوری و رشد/پشتیبانی.
- **Clinic Receptionist**: مدیریت نوبت‌ها، EMR ابتدایی، دایرکتوری و تیکت‌ها.
- ادمین وردپرس به‌صورت خودکار همه‌ی قابلیت‌های اختصاصی (`ms_manage_*`) را دریافت می‌کند.

## شروع سریع (راهنمای پیاده‌سازی آینده)
1. ساخت پلاگین هسته با Module Registry و Service Container.
2. پیاده‌سازی ماژول نوبت‌دهی (MVP): تقویم، رزرو آنلاین، OTP، وضعیت نوبت، پرداخت آنلاین و گزارش ساده.
3. اضافه‌کردن Mini EMR و چاپ نسخه PDF.
4. استقرار روی staging و تنظیم وبهوک پرداخت و SMS.

برای جزئیات کامل به مستندات داخل پوشه‌ی `docs` مراجعه کنید.
